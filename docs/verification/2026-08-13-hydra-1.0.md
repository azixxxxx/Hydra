## Automated gate

`npm run check` exited 0 before the opt-in live gate:

- 22 test files passed and 2 opt-in real-only files were skipped;
- 341 tests passed and 5 real-Claude/isolation tests were skipped;
- ESLint passed;
- strict TypeScript typecheck passed;
- both runtime bundles built;
- plugin validation reported `hydra@1.0.0`.

Both `npm audit` and `npm audit --omit=dev` reported 0 vulnerabilities. After staging the initial tree, `git diff --cached --check` exited 0. Reproducible `dist` files are marked generated in `.gitattributes`; source, tests, scripts, and documentation retain normal whitespace checking. Bundle syntax, private-path, unfinished-work-marker, and privacy scans passed.

A separate clean-copy gate excluded `.git` and `node_modules`, ran `npm ci`, checked the prebuilt bundles before rebuilding, then repeated the full check with the same 341/5 result.

The first public GitHub Actions run (`31696193019`) was intentionally treated as a release gate and failed. It exposed two timing assumptions that local macOS runs had not exercised: a very short Claude process could exit before its process-start marker was read, and a 50 ms timeout could reach a cooperative process before its mock SIGTERM handler was installed. The adapter now keeps a complete fast result only when the process group is gone, kills a surviving orphan group, and still treats process-metadata persistence failure as fatal. Three deterministic regressions cover those branches. The timeout test now accepts bounded cooperative SIGTERM or escalated SIGKILL; a separate leader/child/grandchild fixture continues to prove forced process-tree cleanup. The affected adapter and built-acceptance suites passed 36/36 on the declared Node 20.9.0 floor.

Follow-up public run [`31697483428`](https://github.com/azixxxxx/Hydra/actions/runs/31697483428) passed the complete macOS arm64 matrix on Node 20.9.0 and Node 24, verified that committed bundles were current, reported 0 production dependency vulnerabilities, checked both bundle entry points, and passed the public-source guard.

The final independent delta review reran 69 targeted regressions and the complete mock suite, inspected the published `tools/list` schema branches, and compared generated build output with `dist`. Its verdict was zero remaining P0/P1 blockers and ready to merge. It did not invoke Claude or Hydra models.

The live smoke exposed one stale test expectation. Claude returned one assistant invocation and terminal `num_turns: 2`; Hydra correctly stored these separately as `turns: 1` and `reportedSessionTurns: 2`, while the smoke still expected `turns: 2`. Unit and worker regressions confirmed the intended contract. The assertion was corrected and the Sonnet smoke passed on rerun.

## Closed final-review blockers

- Invalid manifest/config startup cannot run retention with fallback values; degraded startup is read-only.
- Degraded status, result, and budget inspection skip recovery/reconciliation; cancellation is blocked.
- Delegated budget priority is derived from the immutable activation plan, so conditional fan-out cannot be relabeled quality-floor.
- MCP schemas publish a mandatory success/failure discriminator rather than relying on a non-exported refinement.
- Legacy delegation groups retain the old digest and migrate to the canonical 1.0 digest on valid continuation.
- Manifest corruption yields a typed degraded runtime identity instead of killing module import.
